## 👨‍💻 About Me

I'm **Waseem Alhatmi**, a Software Developer passionate about building
modern, practical, and user-focused mobile and web applications.

I enjoy turning real-world ideas into functional software products,
with a strong focus on clean interfaces, practical solutions, and
continuous improvement through hands-on development. Every project I
build starts with a simple question: *what problem does this actually
solve for the person using it?* That question shapes every technical
decision that follows — from the architecture I choose to the smallest
detail in the interface.

My current interests span **mobile app development, web development,
backend systems, databases, and modern software architecture**. I care
about writing code that is not just functional, but maintainable,
readable, and built to grow. I believe good software is never really
"finished" — it evolves as it's used, tested, and improved.

Outside of the specific tools and frameworks I use day to day, what
drives me is the process itself: breaking down a complex problem into
small, solvable pieces, building a working solution, and then refining
it until it feels right. I treat every bug as a lesson and every
finished feature as a stepping stone to the next one.


When I'm not actively coding, I'm usually reading through documentation
for a tool I want to try next, exploring how other developers structure
their projects, or sketching out ideas for the next thing I want to
build. I see every project — finished or not — as part of the same
ongoing process of getting better at this craft.

**Flutter — A Reusable Product Card Widget**

```dart
class ProductCard extends StatelessWidget {
  final String title;
  final String imageUrl;
  final double price;
  final VoidCallback onTap;

  const ProductCard({
    super.key,
    required this.title,
    required this.imageUrl,
    required this.price,
    required this.onTap,
  });

  @override
  Widget build(BuildContext context) {
    return GestureDetector(
      onTap: onTap,
      child: Card(
        clipBehavior: Clip.antiAlias,
        shape: RoundedRectangleBorder(
          borderRadius: BorderRadius.circular(12),
        ),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            AspectRatio(
              aspectRatio: 1,
              child: Image.network(imageUrl, fit: BoxFit.cover),
            ),
            Padding(
              padding: const EdgeInsets.all(8),
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text(title, style: const TextStyle(fontWeight: FontWeight.w600)),
                  const SizedBox(height: 4),
                  Text('\$${price.toStringAsFixed(2)}'),
                ],
              ),
            ),
          ],
        ),
      ),
    );
  }
}
```

**PHP — A Simple API Endpoint Pattern**

```php
<?php
header('Content-Type: application/json');

$conn = new mysqli('localhost', 'user', 'password', 'database');

if ($conn->connect_error) {
    http_response_code(500);
    echo json_encode(['error' => 'Database connection failed']);
    exit;
}

$result = $conn->query('SELECT id, name, price FROM products ORDER BY id DESC');

$products = [];
while ($row = $result->fetch_assoc()) {
    $products[] = $row;
}

echo json_encode(['data' => $products]);
$conn->close();
```

These snippets reflect the style I aim for in every project: clear
naming, minimal nesting, and structure that's easy to extend later.

## 🔄 Development Workflow

My typical approach to building a project follows a consistent process:

1. **Understand the problem** — What is this actually solving, and for whom?
2. **Plan the structure** — Sketch out the architecture before writing code
3. **Build incrementally** — Implement features in small, testable pieces
4. **Test as I go** — Catch issues early rather than at the end
5. **Refactor** — Clean up and simplify once something works
6. **Document** — Make sure the project is understandable to others
7. **Iterate** — Treat every version as a starting point for the next one

```text
Idea → Plan → Build → Test → Refactor → Document → Iterate
```

## 💡 Development Philosophy

> **Build. Learn. Improve. Repeat.**

I believe the best way to grow as a developer is by building real
projects, solving real problems, and continuously improving the
quality of the software I create.

I focus on understanding **why** a solution works — not just making
the code run. A few principles I try to follow in every project:

- **Simplicity first** — the simplest solution that works is usually the right one
- **Readability matters** — code is read far more often than it's written
- **Iteration over perfection** — ship something working, then improve it
- **Learn by building** — real projects teach more than tutorials alone
- **User experience is the priority** — technology should serve the person using it

## ✅ My Code Review Checklist

Before I consider any feature "done," I run through a simple checklist:

- [ ] Does the code do what it's supposed to do, reliably?
- [ ] Is the naming clear enough that I won't need comments to explain it?
- [ ] Is there any unnecessary duplication I can simplify?
- [ ] Would this be easy for someone else to pick up and understand?
- [ ] Have I handled the obvious edge cases?
- [ ] Is the UI consistent with the rest of the application?
- [ ] Is there anything here I'm only doing because it's "quick," not because it's right?

## ♿ A Note on Accessibility & UX

I try to treat accessibility as part of good design, not an
afterthought — readable text sizes, sensible color contrast, and
interfaces that make sense even to someone using the app for the
first time. A product that's technically impressive but hard to use
still isn't finished, in my view.
